The gap between detection and a decision

LLM agent applications connect model outputs to tools, credentials, and deployment configuration. Reviewing only the model misses risks in the surrounding software. Developers need findings tied to code or configuration; security buyers need a scoped assessment they can review.

agent-audit and Argus address different parts of that workflow: the open-source tool supports repeatable detection, while the assessment work turns technical investigation into client-specific security evidence.

agent-audit analyzes agent code and deployment artifacts for risks such as untrusted data reaching dangerous operations, exposed credentials, and excessive permissions. Findings link back to source locations or configuration paths and can be exported into development workflows.

CI/CD integration and rule-level regression tests make detection changes reviewable over time. A scanner result remains an input to an assessment; it does not by itself certify that an application is secure.

Keep the rule count honest

200+GitHub stars; 228 verified on September 10, 2026.

The number 51 refers to unique built-in YAML rule IDs loaded by the rule engine in the verified snapshot. It is not a count of every runtime-emittable finding type or an optional profile's rules. Those surfaces have different definitions and change over time.

A receiver-type false positive also exposed the need for discriminating tests: after correcting the misclassification, I checked the intended true-positive behavior with a control. Removing an unwanted finding is insufficient if the same change suppresses the vulnerability the rule is supposed to detect.

Argus: direct client delivery

As Founder & CEO of Argus Security from February to August 2026, I directly scoped client requirements and delivered third-party AI-agent security audit reports. Those reports were used to address buyer-side CISO requirements during B2B procurement reviews.

The work included an OWASP-aligned assessment of a production healthcare RAG agent. It connected static analysis and threat modeling to a real deployed application, while requiring a clear separation between tool findings, analyst judgment, and the scope of the report.

Client names, confidential findings, and procurement documents are intentionally excluded. This portfolio makes no claim that an assessment alone guaranteed a secure deployment or completed a sale.

Public engineering & research

The source repository and the first-author paper, Agent Audit: A Security Analysis System for LLM Agent Applications, provide public evidence of the analysis approach and developer workflow.

The paper describes a specific evaluation snapshot. Its benchmark results should not be conflated with later repository measurements or the outcome of a client assessment. The transferable work is the connection between detection engineering, measurement discipline, and security communication.
