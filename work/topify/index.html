Start with the customer's workflow

B2B marketing work spans information gathering, analysis, and repeated actions across tools. Adding a model call does not resolve that fragmentation. The product challenge was to translate real SEO and generative engine optimization (GEO) workflows into software that customers could use repeatedly.

I worked directly with customers to scope requirements and turn their operating needs into reusable platform capabilities, then owned implementation and deployment.

System architecture

01 / WorkflowCustomer requirementsReusable marketing capabilities
02 / Integrate30+ APIsConnected information sources
03 / RetrieveHybrid searchBGE-M3 + BM25 + RRF
04 / DeliverLLM workflowsRailway deployment

The platform combined API integrations with hybrid retrieval. BGE-M3 supplied embedding-based retrieval, BM25 supplied lexical matching, and reciprocal rank fusion combined the ranked results before they were used in the LLM workflow.

This gave the application a retrieval layer that could use both semantic similarity and exact terminology. The system was deployed on Railway as part of my end-to-end delivery responsibility.

End-to-end ownership

Translate requirements into reusable capabilities

My role connected customer discovery with workflow design and implementation. The unit of delivery was a usable marketing capability within the platform, with integrations and retrieval supporting the customer task.

Connect the application to its information sources

I built LLM workflows integrating more than 30 APIs and a hybrid retrieval layer over more than 100,000 chunks. That work required coordinating the application workflow with the information available to it.

Carry the system through deployment

I owned Railway deployment alongside implementation. This experience links customer-facing product decisions with the practical work of getting the system running.
